1Bienvenida: el proyecto del Sub-bloque B

Desde hoy trabajas en paralelo sobre dos frentes: en el Sub-bloque A el docente guía la teoría de PWA en vivo, sesión por sesión; en el Sub-bloque B tú construyes un proyecto real que aplica, ese mismo día, el tema que se acaba de ver en fundamentación. El proyecto se llama Atlas 3D de Arquitectura de Software: un catálogo interactivo en 3D de ocho patrones y arquitecturas de software — Arquitectura en Capas, MVC, Árbol Binario, Cliente-Servidor, Cliente-Caché-Servidor, Microservicios, Publicador-Suscriptor y Repositorio — con soporte de realidad aumentada más adelante en el bloque.

El proyecto se enseña a sí mismo: los ocho objetos que vas a poder ver en 3D, al final del Sub-bloque B, van a ser ni más ni menos los mismos patrones que va a usar el código de tu propio proyecto para organizarse. La arquitectura en capas va a ser literalmente la arquitectura de tus carpetas; el árbol binario va a ser literalmente la estructura de datos que guarda el catálogo. No es una coincidencia — es la forma más directa que encontramos de que el contenido y el código se expliquen entre sí. Hoy, sin embargo, arrancamos por la pieza más simple: el proyecto vacío y su manifiesto.

2Por qué crear el proyecto (y no clonarlo)

Clonar un repositorio ya armado es rápido, pero te deja sin entender qué archivo hace qué. Hoy usamos npm create vite@latest, la herramienta oficial de scaffolding de Vite: genera el andamiaje mínimo de un proyecto (configuración, punto de entrada, estructura de carpetas) y te deja ver, uno por uno, los archivos que aparecen [1].

Terminal
npm create vite@latest pwa-ar-objetos3d -- --template vanilla-ts
cd pwa-ar-objetos3d
npm install
npm install three
npm install --save-dev @types/three

El primer comando pregunta el nombre del proyecto y la plantilla — vanilla-ts significa "sin framework, con TypeScript": exactamente lo que necesitamos, porque la interfaz la construimos con Three.js directamente, no con React ni Angular (esos llegan como comparación al final del Sub-bloque B). npm install three agrega la librería de gráficos 3D — la misma API que en las Sesiones 38-39 se reutiliza para realidad aumentada, porque su bucle de dibujo (renderer.setAnimationLoop) es el mismo que exige WebXR [2].

3Arquitectura de carpetas: capas + MVC

Organizamos src/ en cuatro capas, cada una con una única responsabilidad — el mismo patrón Arquitectura en Capas que vas a poder ver en 3D en el propio catálogo [3]:

src/ ├── dominio/ // Modelo — qué es un PatronArquitectura, y el árbol que los guarda │ ├── PatronArquitectura.ts │ └── ArbolCatalogo.ts ├── datos/ // Los 8 patrones iniciales (seed data) │ └── patrones.ts ├── vista/ // Vista — la escena 3D, la lista, y un constructor por patrón │ ├── escena3d.ts │ ├── listaCatalogo.ts │ └── constructores/ └── controlador/ // Controlador — conecta la lista con el Modelo y la Vista └── ControladorVisor.ts

Esas mismas cuatro capas son, además, el patrón MVC: dominio/ + datos/ son el Modelo, vista/ es la Vista, controlador/ es el Controlador. La regla que hace que esto funcione es simple: una capa solo puede importar de la capa que tiene justo debajo (el controlador conoce a la vista y al modelo; la vista y el modelo no se conocen entre sí; nadie conoce al controlador) [3][4].

Mapa de destino, no el punto de partida de hoy: ninguna de estas carpetas existe todavía. Al terminar la sesión de hoy tu proyecto solo tiene el andamiaje que genera npm create vite (src/main.ts, src/style.css, etc.) más tu manifest.json. Cada capa aparece, con su primer archivo real, a medida que el Sub-bloque B avanza — nunca antes de que la guía correspondiente la explique y la construyas en clase.

4El manifest.json del proyecto

Esto ya lo sabes hacer — lo construiste en la Sesión 16. Aplícalo directamente a tu propio proyecto, con sus propios valores:

public/manifest.json
{
  "name": "Atlas 3D de Arquitectura de Software",
  "short_name": "Atlas 3D",
  "description": "Catálogo interactivo en 3D de patrones y arquitecturas de software, con soporte de realidad aumentada.",
  "start_url": "/",
  "scope": "/",
  "display": "standalone",
  "background_color": "#0b1220",
  "theme_color": "#0b1220",
  "icons": [
    { "src": "/iconos/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/iconos/icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "/iconos/icon-512-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}

Nótalo bien: en un proyecto Vite, el manifest y los íconos van en public/ — todo lo que pones ahí se sirve tal cual, desde la raíz (/manifest.json, /iconos/...), sin que Vite lo procese. Enlázalo en index.html igual que en el Gestor de tareas: <link rel="manifest" href="/manifest.json">. Verifícalo en DevTools → Application → Manifest: hoy va a marcar el Service Worker en rojo (llega en la Sesión 28) — el resto debería estar en verde.

Crea tu proyecto

Primer commit y repositorio en GitHub

TAREA INDIVIDUAL · FUERA DE CLASE · 20 MIN
