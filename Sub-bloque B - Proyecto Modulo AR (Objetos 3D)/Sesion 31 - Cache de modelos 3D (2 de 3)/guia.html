Caché de modelos 3D (2/3)

Cache Only, Network Only y Cache First, aplicadas por primera vez al Atlas 3D — sobre los assets que el proyecto ya tiene hoy, como ensayo de lo que viene cuando lleguen los modelos 3D pesados.

Objetivos de aprendizaje

  • ✓Aplicar Cache Only, Network Only y Cache First al sw.js real del Atlas 3D.
  • ✓Reconocer que la elección de estrategia depende del tipo de recurso, no del proyecto — el mismo criterio de la Sesión 20 sobre el Gestor de tareas.
  • ✓Anticipar qué estrategia le tocará a cada tipo de archivo del catálogo 3D cuando los modelos existan de verdad.
  • ✓Verificar en DevTools (Network, modo offline) el comportamiento real de Cache First sobre el Atlas 3D.

Recursos de esta sesión

  • Descargar .zipCheckpoint — cierre de la Sesión 30. El sw.js ya guarda los íconos uno por uno con put() y tiene el caché versionado (atlas3d-v2), pero el manejador de fetch sigue siendo el mismo match() con respaldo a la red — hoy le pones nombre a esa lógica, y la mejoras.

1Esto ya lo viste a fondo en la Sesión 20

Qué es cada una de las tres estrategias más simples — Cache Only, Network Only y Cache First — y qué problema resuelve cada una, ya lo estudiaste con calma en la Sesión 20, con las funciones cacheOnly(), networkOnly() y cacheFirst() implementadas y probadas sobre el Gestor de tareas. No repetimos nada de esa teoría aquí: si el porqué de alguna de las tres no te suena, vuelve primero a esa guía.

Lo que sí toca hoy es distinto: aplicar esas mismas tres funciones al sw.js real del Atlas 3D, que hasta la Sesión 30 solo usaba un match() genérico sin ninguna estrategia con nombre.

2Todavía no hay modelos 3D reales — por eso se ensaya con los íconos

El Atlas 3D, tal como está al cierre de la Sesión 30, sigue sin ningún archivo .glb o .gltf. Lo único que existe para cachear son las tres rutas del shell ('/', '/index.html', '/manifest.json') y los tres íconos del manifest, guardados con put() desde la sesión pasada. Eso alcanza para el ensayo de hoy: los íconos son, exactamente como serán los modelos 3D más adelante, archivos binarios que rara vez cambian una vez publicados — el candidato natural para Cache First.

El mapeo que vale la pena recordar: hoy, "recurso inmutable" = ícono PNG. Más adelante en el Sub-bloque B, "recurso inmutable" = archivo .glb de un modelo publicado. La estrategia que le conviene a uno le conviene al otro — por eso practicar sobre los íconos no es una simplificación artificial, es literalmente el mismo tipo de recurso a menor escala.

3Cache First para los íconos del Atlas 3D

Reemplazamos el manejador de fetch genérico por Cache First — la misma función de la Sesión 20, sin ningún cambio:

public/sw.js (fragmento)
function cacheFirst(peticion) {
  return caches.match(peticion).then(enCache => {
    if (enCache) return enCache;
    return fetch(peticion).then(respuesta => {
      const clon = respuesta.clone();
      caches.open(CACHE_NAME).then(cache => cache.put(peticion, clon));
      return respuesta;
    });
  });
}

self.addEventListener('fetch', event => {
  event.respondWith(cacheFirst(event.request));
});

La diferencia con la Sesión 30 es sutil pero real: antes, si un recurso no estaba en caché, se pedía a la red y ya — sin guardarlo. Ahora, Cache First guarda esa respuesta con put() la primera vez que se pide, así que la segunda vez ya no toca la red en absoluto. Para el shell y los íconos actuales no se nota mucho porque ya estaban precacheados en install — pero es exactamente el mecanismo que hará falta cuando un modelo 3D nuevo se pida por primera vez sin haber sido parte del precache inicial.

Para verificarlo: F12 → pestaña Network, con el filtro "Service Worker" activado. Tras la primera carga, activa el modo offline (Application → Service Workers → Offline) y recarga: el shell y los íconos siguen apareciendo, servidos desde caché.

Resumen de la sesión

  • Cache Only, Network Only y Cache First se estudiaron a fondo en la Sesión 20 — hoy solo se aplican al Atlas 3D, sin repetir la teoría.
  • Los íconos del manifest cumplen hoy el mismo rol que cumplirán los modelos .glb/.gltf más adelante: recursos binarios inmutables, candidatos naturales a Cache First.
