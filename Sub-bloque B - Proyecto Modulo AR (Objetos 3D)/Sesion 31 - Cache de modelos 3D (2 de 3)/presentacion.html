Antes de empezar

Todavía no hay modelos 3D — por eso se ensaya con los íconos

El Atlas 3D, al cierre de la Sesión 30, sigue sin ningún archivo .glb o .gltf. Lo único que existe para cachear son las tres rutas del shell y los tres íconos del manifest, guardados con put() desde la sesión pasada.

El mapeo que vale la pena recordar: hoy, "recurso inmutable" = ícono PNG. Más adelante en el Sub-bloque B, "recurso inmutable" = archivo .glb de un modelo publicado. La estrategia que le conviene a uno le conviene al otro — practicar sobre los íconos no es una simplificación artificial, es el mismo tipo de recurso a menor escala.

Cache First para los íconos del Atlas 3D

La misma función de la Sesión 20 — sin ningún cambio — reemplaza el manejador de fetch genérico.

Cache First · 1.1

cacheFirst(): la misma función de la Sesión 20

public/sw.js (fragmento)
function cacheFirst(peticion) {
  return caches.match(peticion).then(enCache => {
    if (enCache) return enCache;
    return fetch(peticion).then(respuesta => {
      const clon = respuesta.clone();
      caches.open(CACHE_NAME).then(cache => cache.put(peticion, clon));
      return respuesta;
    });
  });
}

self.addEventListener('fetch', event => {
  event.respondWith(cacheFirst(event.request));
});
Reemplazamos el manejador de fetch genérico por Cache First — la misma función de la Sesión 20, sin ningún cambio.
Cache First · 1.2

Qué cambia frente a la Sesión 30, y cómo verificarlo

Antes, si un recurso no estaba en caché, se pedía a la red y ya — sin guardarlo. Ahora, Cache First guarda esa respuesta con put() la primera vez que se pide, así que la segunda vez ya no toca la red en absoluto.

Para el shell y los íconos actuales no se nota mucho, porque ya estaban precacheados en install — pero es exactamente el mecanismo que hará falta cuando un modelo 3D nuevo se pida por primera vez sin haber sido parte del precache inicial.

Para verificarlo: F12 → pestaña Network, con el filtro "Service Worker" activado. Tras la primera carga, activa el modo offline (Application → Service Workers → Offline) y recarga: el shell y los íconos siguen apareciendo, servidos desde caché.
