Caché de modelos 3D (1/3)

La interfaz Cache completa, aplicada por fin al Atlas 3D: put(), open(), keys(), delete() y versionado — sobre los assets que el proyecto ya tiene hoy, como ensayo de lo que viene cuando lleguen los modelos 3D pesados.

Objetivos de aprendizaje

  • ✓Aplicar cache.put() para guardar assets del Atlas 3D uno por uno, con control total, en vez de depender solo de addAll().
  • ✓Versionar el CACHE_NAME del proyecto y limpiar la versión anterior en activate con caches.keys() y caches.delete().
  • ✓Reconocer que put(), open(), keys() y delete() son exactamente la misma interfaz Cache de la Sesión 19 — hoy solo cambia qué se cachea.
  • ✓Verificar en DevTools → Application → Cache Storage que solo existe la versión vigente del caché del Atlas 3D.

Recursos de esta sesión

Descarga esto antes de empezar — es tu Atlas 3D exactamente como quedó al cierre de la Sesión 29, con el Service Worker respondiendo desde el caché para el shell mínimo.

  • Descargar .zipCheckpoint — cierre de la Sesión 29. El sw.js ya intercepta fetch con caches.match(), pero solo escribe en el caché con addAll() dentro de install, sin put() manual ni versionado: eso es lo que agregas hoy.

1Esto ya lo viste a fondo en la Sesión 19

La interfaz Cache completa — qué es caches, qué es un objeto Cache, y cada una de sus ocho operaciones (open, put, addAll, match, delete, keys del caché, caches.keys() y caches.delete()) — ya la estudiaste con calma en la Sesión 19, sobre el Gestor de tareas. Esa guía también explica por qué la Cache Storage API es independiente del caché HTTP del navegador. No repetimos nada de eso aquí: si algo de la lista de abajo no te suena, vuelve primero a esa guía.

Lo que sí toca hoy es distinto: aplicar esa misma interfaz al sw.js real del Atlas 3D, que hasta la Sesión 29 solo usaba dos de las ocho operaciones (open y addAll en install, match en fetch). Hoy entran las cuatro que faltaban.

cache.put(req, res)

Guarda una respuesta específica sin hacer fetch() por dentro — control total. Hoy la usamos para los íconos.

caches.keys()

Lista los nombres de todos los cachés del origen. Hoy la usamos en activate para encontrar versiones viejas.

caches.delete(nombre)

Elimina un caché completo por nombre. Hoy borra cualquier versión que no sea la actual.

Versionado de CACHE_NAME

Cambiar el nombre del caché al actualizar contenido, para poder distinguir lo viejo de lo nuevo.

2Todavía no hay modelos 3D reales — y eso es exactamente el punto

Sé honesto contigo mismo antes de seguir: el Atlas 3D, tal como está al cierre de la Sesión 29, no tiene ningún modelo 3D. No hay archivos .glb ni .gltf en el proyecto, ni una carpeta dominio/ o vista/ que los use — esas capas son, como dijo la Sesión 27, el mapa de destino, no algo que exista todavía. src/main.ts sigue mostrando el mensaje de arranque, y lo único que el Service Worker cachea son tres rutas del shell ('/', '/index.html', '/manifest.json') más, desde hoy, los tres íconos del manifest.

Por qué la sesión se llama "Caché de modelos 3D" entonces: porque cuando los modelos lleguen, más adelante en el Sub-bloque B, necesitarás exactamente la misma interfaz que practicas hoy — put() para guardarlos uno por uno (probablemente no todos con addAll(), porque pueden pesar mucho y convenir cargarlos bajo demanda), y versionado para no dejar modelos viejos ocupando espacio cada vez que actualices el catálogo. Hoy practicamos esa misma interfaz sobre los assets que sí existen — los íconos y el manifest — para que cuando lleguen los archivos pesados ya sepas exactamente cómo cachearlos y versionarlos, sin tener que aprender la API y el proyecto real al mismo tiempo.

3put() manual: los íconos, uno por uno

Hasta ahora, install guardaba todo con una sola llamada a cache.addAll(CORE_ASSETS). Eso funciona bien para el shell, pero es una caja negra: no controlas qué pasa si una descarga falla, ni puedes guardar un asset que no viene de un simple fetch() a una URL fija. cache.put() resuelve eso — recibe la petición (o su URL) y la respuesta por separado, así que tú decides exactamente qué se guarda:

sw.js (fragmento)
const ICON_ASSETS = [
  '/iconos/icon-192.png',
  '/iconos/icon-512.png',
  '/iconos/icon-512-maskable.png',
];

async function guardarIconos(cache) {
  for (const url of ICON_ASSETS) {
    const respuesta = await fetch(url);
    await cache.put(url, respuesta);
  }
}

Es, literalmente, lo que addAll() hace por dentro para cada URL de su lista — solo que aquí lo escribes tú mismo, un asset a la vez. Esa diferencia importa cuando, más adelante, un modelo 3D falle su descarga y quieras decidir tú qué hacer con ese caso puntual, en vez de que toda la lista de install falle de golpe (así funciona addAll(): si una sola URL falla, ninguna se guarda).

4Versionado: caches.keys() + caches.delete() en activate

El Atlas 3D todavía no tenía versionado: CACHE_NAME ha sido 'atlas3d-v1' desde la Sesión 28, sin que activate hiciera nada con los nombres de caché. Hoy lo agregamos — el mismo patrón exacto de la Sesión 19, con el CACHE_NAME real del proyecto:

sw.js (fragmento)
const CACHE_NAME = 'atlas3d-v2'; // antes: 'atlas3d-v1'

self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(nombres =>
      Promise.all(
        nombres
          .filter(nombre => nombre !== CACHE_NAME)
          .map(nombre => caches.delete(nombre))
      )
    ).then(() => self.clients.claim())
  );
});

Sube 'atlas3d-v1' a 'atlas3d-v2' y ese solo cambio deja huérfano el caché anterior — activate lo detecta con caches.keys() (que lista los nombres, no el contenido) y lo elimina con caches.delete(). Sin este bloque, cada actualización futura del Atlas 3D — y en especial cada vez que cambie el conjunto de modelos 3D cacheados — iría acumulando cachés viejos en el disco del usuario para siempre.

5Caso real: el sw.js actualizado del Atlas 3D

Juntando las dos piezas de arriba sobre lo que ya traía la Sesión 29 — el fetch con caches.match() queda exactamente igual, no es el tema de hoy:

public/sw.js
const CACHE_NAME = 'atlas3d-v2';
const CORE_ASSETS = [
  '/',
  '/index.html',
  '/manifest.json',
];
const ICON_ASSETS = [
  '/iconos/icon-192.png',
  '/iconos/icon-512.png',
  '/iconos/icon-512-maskable.png',
];

self.addEventListener('install', event => {
  event.waitUntil(
    caches.open(CACHE_NAME).then(async cache => {
      await cache.addAll(CORE_ASSETS);
      for (const url of ICON_ASSETS) {
        const respuesta = await fetch(url);
        await cache.put(url, respuesta);
      }
    })
  );
});

self.addEventListener('activate', event => {
  event.waitUntil(
    caches.keys().then(nombres =>
      Promise.all(
        nombres.filter(nombre => nombre !== CACHE_NAME).map(nombre => caches.delete(nombre))
      )
    ).then(() => self.clients.claim())
  );
});

self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(
      encontrado => encontrado || fetch(event.request)
    )
  );
});

Para verificarlo: F12 → pestaña Application → sección Cache Storage. Debería aparecer un único caché, atlas3d-v2, con seis entradas: las tres rutas del shell más los tres íconos. Si recargas varias veces y sigues viendo solo atlas3d-v2 en la lista — nunca atlas3d-v1 al mismo tiempo — la limpieza de activate está funcionando.
