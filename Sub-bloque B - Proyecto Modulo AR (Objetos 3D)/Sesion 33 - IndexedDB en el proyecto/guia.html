IndexedDB en el proyecto

Guardar el progreso y las preferencias del usuario del Atlas 3D de forma estructurada y consultable — favoritos, últimos modelos vistos, y una nota de estudio personal por modelo, cifrada con la misma clave derivada por contraseña de la Sesión 22.

Objetivos de aprendizaje

  • ✓Diseñar el esquema de IndexedDB del Atlas 3D: object store, índices, y su justificación según cómo se consulta cada dato.
  • ✓Aplicar CRUD y consultas con índice/cursor al progreso real del usuario: modelos vistos, favoritos, última visita.
  • ✓Reconocer que el mismo patrón de cifrado con clave derivada de la Sesión 22 aplica aquí, para el único campo del Atlas 3D que es genuinamente privado: una nota de estudio personal.
  • ✓Verificar en DevTools → Application → IndexedDB el esquema y los datos reales del Atlas 3D.

Recursos de esta sesión

1Esto ya lo viste a fondo en la Sesión 22

Qué es IndexedDB, cómo se abre y versiona una base de datos, las operaciones CRUD, los cursores, y cómo derivar una clave real con PBKDF2 para cifrar campos sensibles con AES-GCM, ya lo estudiaste con calma en la Sesión 22, sobre el Gestor de tareas. No repetimos nada de esa teoría aquí: si el porqué de onupgradeneeded, un índice, un cursor, o deriveKey() no te suena, vuelve primero a esa guía.

Lo que sí toca hoy es distinto: diseñar el esquema real que el Atlas 3D necesita, y aplicarlo — con las mismas funciones de la Sesión 22, sin reinventarlas.

2Qué necesita guardar el Atlas 3D, y por qué cada pieza va donde va

El Atlas 3D es, hasta hoy, un catálogo que el usuario navega — sin cuenta de usuario ni servidor detrás. Lo que sí tiene sentido guardar localmente, por usuario y por dispositivo, es su progreso: qué modelos ya vio, cuáles marcó como favoritos, y una nota de estudio personal por modelo. Ninguno de esos tres datos es un archivo — son registros estructurados que se consultan por distintos criterios, exactamente el caso de uso para el que existe IndexedDB y no la Cache Storage API de las Sesiones 27-32.

db.js
function abrirBaseDeDatos() {
  return new Promise((resolve, reject) => {
    const peticion = indexedDB.open('atlas3d-progreso-db', 1);

    peticion.onupgradeneeded = event => {
      const db = event.target.result;
      const store = db.createObjectStore('progreso', { keyPath: 'modeloId' });
      store.createIndex('porFavorito', 'favorito', { unique: false });
      store.createIndex('porUltimaVisita', 'ultimaVisita', { unique: false });
    };

    peticion.onsuccess = event => resolve(event.target.result);
    peticion.onerror = event => reject(event.target.error);
  });
}

La clave del store es directamente modeloId (sin autoIncrement, a diferencia del Gestor de tareas): un registro de progreso siempre pertenece a un modelo concreto del catálogo, así que su propio identificador ya es la clave natural. El índice porFavorito permite pintar la sección "Tus favoritos" sin recorrer todo el store; porUltimaVisita permite un "Continuar viendo" ordenado por lo más reciente.

3CRUD y consultas sobre el progreso real

Las mismas funciones de envoltura de la Sesión 22 — agregarTarea(), obtenerTarea(), cursores con índice — se reescriben aquí con los nombres reales del Atlas 3D, sin ningún cambio de fondo en cómo funcionan:

db.js
function marcarModeloVisto(db, modeloId) {
  return new Promise((resolve, reject) => {
    const tx = db.transaction('progreso', 'readwrite');
    const store = tx.objectStore('progreso');
    const peticion = store.get(modeloId);

    peticion.onsuccess = () => {
      const registro = peticion.result || { modeloId, favorito: false, notaCifrada: null, notaIv: null };
      registro.ultimaVisita = Date.now();
      const escritura = store.put(registro);  // put(): crea o actualiza, nunca falla por clave repetida
      escritura.onsuccess = () => resolve(registro);
      escritura.onerror = () => reject(escritura.error);
    };
    peticion.onerror = () => reject(peticion.error);
  });
}

function alternarFavorito(db, modeloId) {
  return new Promise((resolve, reject) => {
    const tx = db.transaction('progreso', 'readwrite');
    const store = tx.objectStore('progreso');
    const peticion = store.get(modeloId);

    peticion.onsuccess = () => {
      const registro = peticion.result || { modeloId, favorito: false, ultimaVisita: null, notaCifrada: null, notaIv: null };
      registro.favorito = !registro.favorito;
      const escritura = store.put(registro);
      escritura.onsuccess = () => resolve(registro.favorito);
      escritura.onerror = () => reject(escritura.error);
    };
  });
}

function obtenerFavoritos(db) {
  return new Promise((resolve) => {
    const resultado = [];
    const indice = db.transaction('progreso', 'readonly').objectStore('progreso').index('porFavorito');
    const cursor = indice.openCursor(IDBKeyRange.only(true));

    cursor.onsuccess = event => {
      const c = event.target.result;
      if (c) { resultado.push(c.value); c.continue(); }
      else resolve(resultado);
    };
  });
}

marcarModeloVisto() usa put() deliberadamente, no add(): la primera vez que se visita un modelo crea el registro, y cada visita siguiente solo actualiza ultimaVisita — con add(), la segunda visita fallaría por clave repetida. obtenerFavoritos() es exactamente el mismo patrón de cursor-con-índice de la Sesión 22, aplicado al índice porFavorito en vez de porPrioridad.

4La nota de estudio: el único campo que sí vale la pena cifrar

De los tres datos que guarda el Atlas 3D, dos son inofensivos si alguien más los ve (qué modelos visitaste, cuáles marcaste favoritos). El tercero — una nota de estudio personal por modelo, que el usuario escribe para sí mismo mientras repasa — sí es un campo privado en el mismo sentido que la "notaPrivada" del Gestor de tareas en la Sesión 22. Se cifra con exactamente la misma clave derivada por contraseña de esa sesión, reutilizando cifrarTexto() y descifrarTexto() sin cambiarles una línea:

db.js
async function guardarNotaDeEstudio(db, clave, modeloId, texto) {
  const { cifrado, iv } = await cifrarTexto(clave, texto);  // función de la Sesión 22, sin cambios
  const tx = db.transaction('progreso', 'readwrite');
  const store = tx.objectStore('progreso');
  const registro = (await new Promise(r => { store.get(modeloId).onsuccess = e => r(e.target.result); }))
    || { modeloId, favorito: false, ultimaVisita: null };
  registro.notaCifrada = cifrado;
  registro.notaIv = iv;
  return new Promise((resolve, reject) => {
    const escritura = store.put(registro);
    escritura.onsuccess = () => resolve();
    escritura.onerror = () => reject(escritura.error);
  });
}

No se reinventa ningún algoritmo ni se deriva una segunda clave: es la misma clave, la misma sal, y las mismas funciones cifrarTexto()/descifrarTexto() de la Sesión 22, aplicadas a un campo distinto. Ese es exactamente el punto de haber aprendido el patrón por separado de cualquier proyecto: se reutiliza tal cual, sin volver a resolver el problema criptográfico.

Para verificarlo: DevTools → Application → IndexedDB → atlas3d-progreso-db → progreso. Cada registro debe mostrar favorito y ultimaVisita en texto plano y legible, y notaCifrada como un ArrayBuffer de bytes — nunca el texto de la nota.

Resumen de la sesión

  • IndexedDB, sus operaciones CRUD, los cursores y la derivación de claves con PBKDF2 se estudiaron a fondo en la Sesión 22 — hoy solo se aplican al Atlas 3D, sin repetir la teoría.
  • El esquema real del Atlas 3D: un store progreso con clave modeloId, e índices por favorito y por ultimaVisita — cada uno justificado por cómo se va a consultar.
  • put(), no add(), es la operación correcta para "crear o actualizar el progreso de este modelo", porque una misma clave se escribe muchas veces.
  • De todo lo que guarda el Atlas 3D, solo la nota de estudio personal justifica cifrarse — se reutiliza, sin cambios, la clave y las funciones de cifrado de la Sesión 22.
